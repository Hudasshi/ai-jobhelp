# 可行性分析

**项目名称**：基于 SpringBoot 与 Vue3 的 AI 求职智能体系统设计与实现
**文档版本**：v1.0
**创建日期**：2026-09-20

---

## 一、技术可行性

### 1.1 技术栈成熟度

| 技术层 | 选型 | 成熟度 | 说明 |
|--------|------|--------|------|
| 前端 | Vue 3 + Vite + Element Plus | 成熟稳定 | 生态完善，社区资料丰富，组件库开箱即用 |
| 后端 | SpringBoot 3.x + MyBatis-Plus | 成熟稳定 | 业界主流 Java 企业级开发框架，官方文档齐全 |
| 数据库 | MySQL 8 | 成熟稳定 | 关系型数据库，支持复杂业务数据建模 |
| 缓存/计数 | Redis | 成熟稳定 | 用于用户每日 AI 调用配额计数 |
| AI 集成 | LangChain4j + 第三方大模型 API（DeepSeek/通义千问） | 成熟可用 | 提供 AiServices/@Tool/ChatMemory 能力，与业务需求一一对应 |
| 文档解析 | Java PDF/Word 解析库 | 成熟可用 | 支持简历文本抽取 |
| 部署 | 云服务器（阿里云/腾讯云学生机） | 成熟 | 部署流程标准，运维成本低 |

### 1.2 关键技术点实现路径

| 关键技术点 | 实现方案 | 可行性依据 |
|-----------|---------|-----------|
| 简历解析 | 上传 PDF/Word 简历，后端用解析库抽取文本 | 文档解析技术成熟，已有大量开源方案 |
| 结构化输出 | 大模型 API 开启 JSON Mode + JSON Schema 约束 | 主流大模型 API 原生支持，前端可直接渲染 |
| Function Calling | LangChain4j @Tool 注解声明工具，Agent 调用"提取 JD 字段/写入看板" | 框架成熟，官方有完整示例 |
| 业务记忆 | 用户档案、简历版本、投递历史作为上下文注入 | 基于数据库查询组装 Prompt，实现简单 |
| 容错重试 | JSON 解析失败自动重试（指数退避 1s→2s→4s，最多 3 次），仍失败降级为简化 Prompt | 纯后端逻辑实现，无技术障碍 |
| Token 控制 | 入口校验 token 数 + 结构化字段截断 + 超长摘要压缩 | 有明确实现路径，可砍约 40% 长度 |
| 配额控制 | Redis 计数器（user:date），请求前校验、成功后扣减 | Redis 原子操作，实现成熟 |
| 权限安全 | JWT 令牌鉴权 + 角色权限控制 + SQL 注入/XSS 防护 | 均有成熟框架与最佳实践 |

### 1.3 开发团队能力匹配

- 项目发起人具备 Java（Spring Boot、JDBC、MySQL）与 Vue3 前端基础，与核心技术栈直接匹配；
- 大模型 API 使用门槛低（HTTP 调用即可），且项目定位为"应用层封装"，不涉及模型训练；
- 计划采用"先裸 HTTP 调通 DeepSeek 理解本质，再由 LangChain4j 接管"的渐进学习路径，降低新框架学习风险。

### 1.4 技术风险与对策

| 风险 | 概率 | 影响 | 对策 |
|------|------|------|------|
| 第三方 API 不稳定，JSON 输出偶发格式错乱 | 中 | 中 | JSON Mode 强约束 + 指数退避重试 + 降级方案 + 原始响应日志 |
| Token 长度限制，简历+JD 超限 | 中 | 中 | 入口校验 + 智能截断 + 摘要压缩兜底 |
| LangChain4j 学习成本 | 低 | 中 | 官方文档 + 先裸调 API + 分阶段攻克 |
| AI 输出质量不稳定 | 中 | 高 | 准备垂直语料（真实简历样本）多轮调试 Prompt，评测集验证打分一致性 |

**小结**：技术选型全部为成熟主流技术，关键难点均有明确实现路径与风险预案，**技术可行性成立**。

## 二、经济可行性

### 2.1 开发成本

| 成本项 | 说明 | 估算 |
|--------|------|------|
| 人力成本 | 单人开发，无外聘 | 0 元 |
| 开发时间 | 每周约 5 小时，共 20 周 | 时间成本可控 |
| 开发工具 | IDEA / VS Code 社区版、Git | 0 元 |

### 2.2 运行成本

| 成本项 | 单价 | 周期估算 |
|--------|------|---------|
| 云服务器（学生机） | 约 ¥9.9/月 | MVP 周期（约 5 个月）合计约 ¥50 |
| 大模型 API | 约 ¥0.05/次诊断 | 免费用户每日 1 次；100 用户 × 1 次/日 × 30 天 ≈ ¥150/月（峰值） |
| 域名（可选） | 约 ¥50/年 | 可先使用 IP+端口访问，非必需 |

> 说明：MVP 及毕业设计阶段以自用 + 同学试用为主，实际 API 调用量远低于上述峰值，运行成本可控制在百元量级以内。

### 2.3 成本对比与收益前景

- **对比人工服务**：淘宝简历修改 50~300 元/次，本系统单次 AI 诊断成本约 ¥0.05，仅为人工服务的千分之一量级，具备显著的替代价值；
- **付费意愿**：需求分析访谈已验证目标用户存在付费行为或付费意愿（8 人中至少 3 人有过付费行为或强烈意愿即达标）；
- **盈利模式（远期）**：按次付费（9.9 元/次）或会员订阅（29 元/月）。按项目动机排序，盈利优先级最低，MVP 阶段只做配额限次与预留付费接口，不实现真实支付，避免无商户资质的合规问题；
- **风险预案**：若付费意愿验证不通过，转为纯工具形态，通过广告或简历模板售卖变现。

**小结**：项目总投入低（百元级运行成本 + 个人时间），相对人工服务具有数量级成本优势，即使不考虑盈利也不构成经济负担，**经济可行性成立**。

## 三、操作可行性

### 3.1 用户操作层面

- 系统为 B/S 架构网页应用，用户无需安装客户端，浏览器访问即可使用；
- 核心操作简单：上传简历文件（PDF/Word）+ 粘贴目标岗位 JD → 获取结构化诊断报告；投递记录支持 AI 自动解析 JD 回填，减少手动输入；
- 界面基于 Vue3 + Element Plus 构建，交互友好，符合用户习惯；
- 诊断报告支持 Markdown 渲染展示与导出（PDF/Markdown），使用门槛低。

### 3.2 开发与运维层面

- 开发节奏明确：开题报告已制定 20 周分阶段进度计划（准备→设计→开发→完善→冲刺），每周约 5 小时可完成；
- 采用 Git + GitHub 版本管理，GitHub Issues + Projects 跟踪任务，过程可控；
- 部署简单：前后端分离项目，前端可部署 Vercel/Netlify（免费），后端部署云服务器，有标准操作流程；
- 项目发起人即第一用户，可快速获取反馈、迭代验证。

### 3.3 推广运营层面

- 冷启动路径清晰：自己先用 → 同学试用 → 春招时间节点推广；
- 已有种子用户渠道：需求访谈阶段即与 5~8 名求职同学建立联系，可转化为首批测试用户；
- 目标明确：2027 春招期间服务 100+ 技术岗应届生，具备时间窗口优势。

**小结**：用户操作门槛低、开发计划可执行、部署运维成熟、推广路径清晰，**操作可行性成立**。

## 四、法律可行性

### 4.1 技术使用合规

- 系统对接 DeepSeek、通义千问等第三方大模型 API，均通过官方开放平台合法申请与调用，遵守其服务条款，不涉及模型窃取或越权使用；
- 系统不训练、不微调自有大模型，不存在训练数据版权争议；
- 不自动爬取招聘网站数据，规避《反不正当竞争法》与平台用户协议相关风险（JD 文本由用户手动粘贴提供）。

### 4.2 数据安全与用户隐私

| 合规要点 | 措施 |
|---------|------|
| 传输安全 | 简历等敏感文件经 HTTPS 传输 |
| 存储安全 | 数据库中敏感信息加密存储，API Key 仅存后端 |
| 权限控制 | JWT 鉴权 + 普通用户/管理员角色隔离 |
| 用户权利 | 明确隐私协议，支持用户一键删除全部个人数据 |
| 日志审计 | 登录日志、AI 调用日志、异常日志留痕，便于排查与审计 |

### 4.3 AI 内容合规

- 系统定位为求职辅助工具，只输出诊断建议与优化措辞，不替用户编造经历；
- 针对 AI 幻觉风险，界面明确提示"所有 AI 输出内容需用户人工审核"，符合《生成式人工智能服务管理暂行办法》关于内容真实性与标识的相关要求；
- 语料来源合法：自写简历、访谈对象脱敏简历、牛客公开简历、手动复制 JD、LLM 合成评测集，均不涉及未授权个人信息采集。

### 4.4 商业模式合规

- MVP 阶段不实现真实支付（个人无微信/支付宝商户资质），只做配额限次与预留付费接口，规避无证经营风险；
- 正式商业化前再评估主体资质与支付合规要求。

**小结**：技术使用、数据安全、AI 内容与商业模式各环节均有明确合规措施，**法律可行性成立**。

## 五、结论

### 5.1 综合评估

| 维度 | 评估结论 | 关键依据 |
|------|---------|---------|
| 技术可行性 | ✅ 可行 | 技术栈全部成熟，关键难点有实现路径与风险预案 |
| 经济可行性 | ✅ 可行 | 总投入百元级，成本仅为人工服务千分之一 |
| 操作可行性 | ✅ 可行 | 用户门槛低，20 周开发计划明确，推广路径清晰 |
| 法律可行性 | ✅ 可行 | 第三方 API 合法调用，数据安全与 AI 内容合规措施完备 |

### 5.2 总体结论

**本项目在技术、经济、操作、法律四个维度均具备可行性，可以立项开发。**

项目采用成熟的全栈技术组合与低成本的第三方大模型 API 方案，以应用层智能体封装为核心（不训练大模型），既规避了高昂的算力与合规成本，又聚焦"简历诊断→投递管理→模拟面试"的完整求职业务流程，具备明确的实际应用价值与研究意义。项目发起人兼具目标用户与开发者双重身份，拥有匹配的技术基础与清晰的 20 周实施计划，风险总体可控。

### 5.3 实施建议

1. 严格按开题报告进度计划推进，MVP 优先完成登录注册、AI 简历诊断、投递看板与管理员基础功能（P0 级）;
2. 开发过程中持续积累垂直语料并迭代 Prompt，将"AI 诊断效果"作为核心质量关卡；
3. 重视数据安全：敏感字段加密、HTTPS 传输、隐私协议、一键删除功能必须落地；
4. 保持"不自动爬取、不编造经历、输出需人工审核"三条合规底线；
5. 若第三方 API 调用量上升，及时启用成本熔断与配额控制，保证运行成本可控。
